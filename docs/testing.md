## 外网发送已接收但看不到输出

2026-10-11 用户反馈外网发送 prompt 显示已接收、会话运行中，但经常没有模型输出。代码确认发送回执通过 HTTP，而连续输出主要依赖 WS；此前详情仅在进入页面、发送成功、收到 history.sync、重连和返回前台时拉取。没有持续核对历史，WS 握手也没有超时；主动关闭假死连接仍等待原生 close 回调。正常 pong 不证明会话增量完整，缺失事件序号此前也会被直接跳过。

当前前台会话在 WS 未连接时设置 5 秒详情核对间隔；连接在线的 running、waiting_approval 或 unknown 会话设置 10 秒，其余 30 秒。React Query 在查询数据更新后重置间隔，频繁的正常事件会延后自动核对；因此不是严格的输出延迟保证。HTTP 请求禁用缓存、仍保留原有 20 秒超时；同一查询合并在途请求，页面后台暂停轮询，重新显示和 online 事件立即核对。迟到快照仍不能回滚新事件或权限；发送、审批、恢复不参与定时重试。动作区显示内容核对时间与“刷新输出”，核对失败保留旧内容并明确提示重试，不用连接状态或成功回执冒充输出已同步。同 ID 的正式回复通过 HTTP 恢复后清理临时流式缓冲，避免最终事件丢失时重复显示片段。

WS 握手超过 12 秒后退役旧连接并退避重连，不依赖旧 close 回调；心跳判假死和 send 抛错同样退役。旧连接迟到的 open、close 和消息不能干扰新连接。已建立序号水位后出现缺号时暂停该会话增量，重建快照后从快照序号重新订阅，恢复期间后续残缺增量不能推进水位。快照临时失败仍按原逻辑重试。

Android 触摸设备聚焦会话输入栏后，等待约 750 毫秒（轮询可能使实际触发稍晚）；如果没有键盘边界，也没有至少 80 像素的区域缩小，则临时启用顶部输入栏，同时尝试关闭无反馈的 API 遮挡模式，让浏览器恢复原生缩放处理。收到有效反馈后退出回退；本次聚焦已收到过有效反馈时，键盘收起不会误触发回退。失焦延迟约 400 毫秒恢复底部，保证发送按钮不会在点击结束前移走。不会改写用户保存的手动顶部选项。输入框聚焦也可能使用外接键盘，回退不是键盘已打开的可靠判定；没有边界时也不能保证输入栏精确贴住键盘上沿。

在桌面入口的设置页检查并更新页面后，先返回会话弹出键盘、输入文字，再进入设置 →“输入框仍被键盘遮挡？”→“复制布局诊断”。报告仅包含前端版本、浏览器、安装模式、键盘/页面尺寸、输入框位置及输入布局（`bottom` / `auto-top` / `manual-top`）；不记录输入内容、配对令牌、地址或会话 ID，也不自动上传。复制失败时可长按下方文本框全选复制。自动回退尝试释放遮挡后 `keyboardOverlay` 可以为 false，这是预期处理。

同一入口可以勾选“会话输入栏固定在顶部（兼容模式）”，让输入栏始终位于会话顶部，减少对设备键盘尺寸报告的依赖。手动选项默认关闭，选择保存在该入口的本地存储中，重新打开仍保留；取消勾选恢复自动布局策略。它是可用性回退方式，不能替代对键盘上方自动跟随的真机验收。

`e2e/standalone-keyboard.spec.ts` 在两个 Chromium 项目中分别验证完全无尺寸反馈、browser 模式的桌面快捷入口、直接遮挡、无尺寸事件、创建任务及顶部兼容模式，共 12 项通过。测试使用生产构建和真实 Service Worker，模拟安装标志、键盘/可见区域信号；有效 API 用例只有启用 `overlaysContent` 后才提供键盘尺寸，以防漏判被模拟实现掩盖。无反馈用例模拟 Android 触摸能力并始终返回零键盘尺寸和不变的区域高度，增加实际覆盖输入框的元素，验证自动顶部输入、草稿、诊断、发送仅一次及失焦恢复；移动项目实际通过触摸发送。截图确认模拟遮挡时输入栏和发送按钮可见。测试不会弹出实体 Android 键盘，也不等同于 WebAPK 安装。自动化通过后，当前修改的真机恢复情况仍待用户确认。
