# AgentLink 系统通知

在手机更新 AgentLink 页面，进入「设置 → 任务通知」，点击「开启任务通知」并允许系统通知。随后点击「发送测试通知」，确认手机通知栏实际出现通知，再测试锁屏或关闭页面后的接收。点击通知会打开同一网址下的原会话；配对信息仍由手机本地保存，不放进通知链接。

需要 HTTPS（本机开发的 localhost 除外）、支持 Web Push 的浏览器及通知权限。小米浏览器生成的桌面入口不一定支持，设置页会检查能力并明确提示；桌面快捷方式与浏览器可能有不同的权限和推送能力，应在实际使用的入口开启并测试。省电限制、浏览器推送服务和手机网络也会影响送达。相关机制见 [MDN Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API)。

任务通知以一次指令对应的运行轮次为单位：正常结束通知完成，异常结束通知出错；手动中止、空闲或失联不通知完成。首次打开历史中已完成的会话不会补发。后台已观察到运行或等待审批的任务，进入终态时才通知，无法确认的历史不推测为完成。很短、完全发生在后台断线或未观察期间的任务可能无法补发。

手机页面不必保持打开，电脑上的 AgentLink daemon 与任务进程需要运行。只要有通知订阅，后台每 30 秒进行一次只读会话状态同步，并保留已有 IPC 跟随；不会自动恢复、fork、发送指令或审批。首次开启前，先打开一次首页，让正在执行的任务进入观察范围。

通知使用浏览器厂商的 Web Push 服务，消息由后台按标准加密并签名；不需要额外的 ntfy App。默认只含会话名称及完成/出错提示，不附带回答正文、命令内容或配对令牌。私钥、设备订阅、任务状态与重试队列保存在电脑的 `~/.agentlink/push.db`，不纳入 Git。

失败的通知落盘后退避重试，最长保留 24 小时；重试沿用相同通知标签，减少重复提醒。推送服务明确返回失效订阅时移除该设备，需要重新开启。设置页显示的「推送服务已接受」仅表示服务接受请求，并不证明手机已显示；最终送达必须通过手机实测确认。关闭任务通知先撤销后台订阅，再退出浏览器订阅；解除配对也先关闭该设备通知。轮换配对令牌会撤销所有旧设备订阅。

现有 Service Worker 继续负责 PWA 更新和离线缓存，通过 `push-worker.js` 处理推送与点击；通知功能不会自动重载页面或重新发送任务。服务器端使用 [web-push](https://github.com/web-push-libs/web-push) 构造标准请求，发送时禁止重定向并限制总等待时间；仅接受支持的浏览器厂商推送地址。
