## 一、网络基础 —— 一切的地基

### 1.1 IP 地址与端口：门牌号和房间号

把互联网上任何一台机器想成一栋楼：

- **IP 地址**是门牌号（如 `1.2.3.4`），定位到"这栋楼"；
- **端口**是房间号（0~65535），定位到"楼里哪个服务"。

一台机器上同时跑很多服务，靠端口区分。你的系统里：

| 端口 | 谁在听 | 在哪台机器 |
|---|---|---|
| 8799 | AgentLink daemon | 家里 PC |
| 7000 | frps（隧道服务端） | VPS |
| 443 | Caddy（HTTPS） | VPS |
| 22 | sshd（SSH 登录） | VPS |

"XX 端口不通"永远是排障第一问——比如 frpc 连不上 7000，十有八九是防火墙没放行（见 2.4）。

📍 对照你的系统：PC 上 `netstat -ano | findstr 8799` 能看到 daemon 在监听；
`8799` 后面跟的数字就是进程 PID，可以用它查是谁。

### 1.2 内网 / 外网 / NAT：为什么家里电脑没有公网 IP

你家路由器从运营商拿到**一个**公网 IP，然后自己搞了个 `192.168.x.x` 的内网，
所有设备共享这一个出口——这套机制叫 **NAT**（网络地址转换）。

```
手机/电脑 ──┐
            ├─→ 家里的路由器（NAT）──→ 运营商 ──→ 互联网
电视/平板 ──┘
```

NAT 的关键限制：**只允许"从里往外"主动发起连接**。外面的人不能主动敲你家
电脑的门——路由器不知道该转给谁。这就是为什么：

- 你在家能访问任何网站（你主动出去的）；
- 手机在外面**无法直接连** `http://你家电脑:8799`（外面敲不进来）。

顺便：`192.168.x.x`、`10.x.x.x`、`172.16-31.x.x`、`127.0.0.1` 都有特殊含义——
最后一项 `127.0.0.1`（localhost）是"我自己"，只有本机能访问。VPS 上 Caddy
把流量转给 `127.0.0.1:8799`，就是"转给本机上的 frps"，外网摸不到这个口。

**所以整套架构的存在理由**：VPS 有公网 IP、谁都敲得到；家里 PC 在 NAT 后面、
谁都敲不到 → 让 PC **主动**向 VPS 发起连接（NAT 允许），把这条连接当管道用。
这就是第四章"内网穿透"。

### 1.3 TCP 长连接：为什么会"假死"

WebSocket（WS）是浏览器里的**长连接**：连一次、一直开着、服务器随时推消息。
它建立在 TCP 上，而 TCP 有个著名的坑——**半开连接（half-open）**：

> 网络闪断瞬间，两边都以为连接还在（没有收到任何"关门"通知），
> 实际上包已经在路上全丢了。你发消息 → 石沉大海；对方发消息 → 你也收不到。

手机 WiFi 切换、电梯里信号丢失，都极易造成半开。表现就是：页面开着，
内容再也不更新——**AgentLink 曾经的"模型信息显示不全"**，最后一层原因就是它。

解法是**应用层心跳**：客户端每 20 秒发一个 ping，45 秒收不到 pong 就认定
连接已死，主动断开重连（重连后按序号补发错过的消息）。

📍 对照你的系统：`web/src/api/ws.ts` 里的 `PING_INTERVAL_MS` / `PONG_STALE_MS`。

### 1.4 DNS：域名如何变成 IP

人们记不住 IP，所以有了域名系统。它是一棵**分层委派**的树：

```
. (根)
 └─ xyz. (顶级域，由注册局 CentralNic 运营)
     └─ 你的域名.xyz (NS 记录指向 DNSPod 的服务器)
         └─ A 记录 → <VPS_IP>
```

查询一次域名时发生的事：

1. 问"根"服务器 → 去 xyz 注册局；
2. xyz 注册局说"这域名的 DNS 在 DNSPod"（NS 委派）；
3. DNSPod 说"A 记录是 `<VPS_IP>`"。

三个你亲身踩过的点：

- **委派是注册商推给注册局的**——你在腾讯云控制台看到一切正常，但注册局的
  zone 里还没有，全球就都查不到（那次 `dig @x.nic.xyz` 返回 NXDOMAIN）。
  "改一下再改回来"强制重推，就是解这个。
- **负缓存**：解析器会把"查无此域名"也缓存一小段（通常 ≤15 分钟）。
  所以"权威服务器已经好了，公共 DNS 还说没有"是正常现象，等一会就好。
- **TTL**：每条记录的"保鲜期"。改动记录后，旧的缓存最多再活一个 TTL。

📍 对照你的系统：本机 `nslookup <你的域名>` 查的是本机视角（会被 Clash 的
假 IP 污染！见 5.2）；查**真实**状态用 DoH：
`curl -s 'https://1.1.1.1/dns-query?name=<你的域名>&type=A' -H 'accept: application/dns-json'`

### 1.5 域名的三层世界：注册商、注册局、实名/备案

- **注册商**（Registrar）：卖域名的商店（腾讯云/DNSPod、阿里云、Namecheap）。
- **注册局**（Registry）：每个顶级域的"央行"（.xyz 是 CentralNic，.com 是 Verisign）。
  你的域名最终登记在注册局的数据库里，DNS 委派也在那里生效。
- **whois**：注册局数据库的公开视图。`whois <你的域名>` 能看到注册时间、
  DNS 服务器、状态码（如 `serverHold` = 被暂停解析）。

**实名认证 vs ICP 备案**——两个常被混淆的东西：

| | 实名认证 | ICP 备案 |
|---|---|---|
| 谁要求 | 工信部（对注册人身份） | 工信部（对网站服务） |
| 什么时候要 | 在中国注册商买域名就要 | **大陆境内服务器**用域名开 80/443 才要 |
| 不过的后果 | 域名被 serverHold，全球解析不到 | 云厂商直接封 80/443 端口 |

你的服务器在香港（境外），所以**不需要备案**；域名买了就要实名，是另一码事。

## 二、Web 安全 —— 为什么每一步都要证书

### 2.1 HTTP / HTTPS / WS / WSS

- **HTTP**：明文。中间任何设备（WiFi 路由、运营商、骨干网）都能完整看到
  你发的内容——包括你的登录 token。
- **HTTPS**：HTTP + TLS 加密。中间人只能看到"你在和谁说话、说了多少字节"，
  看不到内容。**WS 之于 HTTPS，就是 WSS**（WebSocket 的加密版）。

AgentLink 的 token 会出现在两个地方：HTTP 头（`Authorization: Bearer ...`）
和 WebSocket 的 URL 参数里。走公网若不加密 = 把家门钥匙 broadcast 出去。
这就是"任何公网暴露必须 HTTPS"的铁律来源。

### 2.2 TLS 证书与 CA

加密要有密钥，但**怎么证明"lingtei.xyz 真的是你的"**？这靠**证书颁发机构
（CA）**——浏览器信任的一批机构，它们核实域名所有权后给你的域名签发证书。

Let's Encrypt 是最大的免费 CA，签发完全自动化：

1. 你向它证明"我控制这个域名"（在服务器上放一个随机文件让它来查，
   叫 HTTP-01 验证，走 80 端口）；
2. 它签发 90 天有效期的证书；
3. 到期前自动续期。

你什么都不用做的原因：Caddy 把这三步全包了（所以叫"自动 HTTPS"）。

📍 对照你的系统：`/etc/caddy/Caddyfile`（VPS 上）只有两行，证书存在
`/var/lib/caddy` 里，续期日志 `journalctl -u caddy`。

### 2.3 反向代理：Caddy 在 VPS 上干嘛

**正向代理**替客户端出去（如 Clash）；**反向代理**替服务器接收——
站在真服务前面，负责"门面"（HTTPS 证书、压缩、转发），真服务可以
安心只讲 HTTP。

```
手机 ──HTTPS:443──▶ Caddy（持有证书、解密、压缩）
                      │ 解密后内网转发
                      ▼
                 127.0.0.1:8799（frps ──隧道──▶ 家里 PC 的 daemon）
```

好处：daemon 完全不用管证书/压缩/HTTPS 细节；证书集中在 Caddy 一处续期。
nginx 是同类里最出名的，Caddy 赢在"零配置自动 HTTPS"。

### 2.4 防火墙的两层

腾讯云轻量的"防火墙"和服务器内部的是**两道独立的门**：

1. **云控制台防火墙**（网页上配）：在流量进你服务器**之前**过滤。
   默认只开 22/80/443/ICMP——这就是那次 frpc 连不上 `:7000` 的原因：
   frps 明明在监听，但包根本到不了服务器。**这层只能你在网页上加规则。**
2. **系统内防火墙**（iptables/nftables/ufw）：包进来之后 Linux 自己再过滤
   一道。我们的 VPS 没装（`iptables: command not found`），所以只有第一层。

安全原则：**最小开放**。最终形态是 VPS 只开 22（SSH）、443（HTTPS）、
7000（frp 隧道）；8799 只绑 `127.0.0.1`，外网根本摸不到。

## 三、Linux 服务器入门 —— VPS 里那头

### 3.1 VPS / 轻量应用服务器 / CVM

- **VPS**（Virtual Private Server）：一台物理服务器用虚拟化切成多份，
  你租其中一份，有独立 IP、独立系统、root 权限。邻居互相看不见。
- 腾讯云的两种卖法：**CVM**（云服务器，全功能、按需计费，略贵）和
  **轻量应用服务器**（Lighthouse，打包好流量包+带宽，便宜，个人够用）。
  同价位下轻量给的更多，所以个人选轻量。
- 选**香港/东京**等境外地域：不用备案、即买即用；代价是晚高峰线路可能
  拥塞（这就是有人愿意买 CN2 GIA 优化线路的原因，见第八章）。

### 3.2 Debian 与 shell 基础

你 VPS 上的系统是 **Debian 12**（Linux 发行版之一，以稳著称）。我们用过的命令：

| 命令 | 干什么 | 例子 |
|---|---|---|
| `apt-get install -y xxx` | 装软件（Debian 的软件仓库） | 装 caddy、dnsutils、whois |
| `curl -s URL` | 发 HTTP 请求看响应 | `curl -o /dev/null -w '%{http_code}' URL` 只看状态码 |
| `ss -tlnp` | 看哪些端口在监听、哪个进程 | 排障第一刀 |
| `systemctl start/stop/restart xxx` | 管理服务 | `systemctl restart frps` |
| `journalctl -u xxx -n 20` | 看某服务的日志 | Caddy 证书为什么没签下来 |
| `dig @DNS服务器 域名 A` | 手工查 DNS（绕过缓存） | `dig @x.nic.xyz <你的域名> NS` |
| `whois 域名` | 查注册局记录 | 看 serverHold 状态 |

`root` 是 Linux 的超级管理员（Windows 的 Administrator），我们所有操作
都以 root 执行——个人 VPS 常态，但要配好密钥登录（3.4）。

### 3.3 systemd：开机自启 + 崩溃拉起

**systemd** 是 Linux 的"总管"（1 号进程），管理所有后台服务。给它写一个
描述文件（unit），你的程序就获得：开机自启、崩溃自动重启、统一日志。

📍 对照你的系统：`/etc/systemd/system/frps.service`——

```ini
[Unit]
Description=frp server (AgentLink relay)
After=network.target

[Service]
ExecStart=/usr/local/bin/frps -c /etc/frp/frps.toml
Restart=on-failure        ← 崩了自动拉起
```

常用操作：`systemctl enable --now frps`（开机自启+立刻启动）、
`systemctl is-active frps`、`journalctl -u frps -n 20`。

Windows 侧的对应物是**计划任务**（见 5.1）——两个系统各有各的"总管"。

### 3.4 SSH：密码 vs 密钥

**SSH** 是远程登录服务器的加密通道（22 端口）。两种登录方式：

- **密码**：你知道密码就能进 → 会被暴力破解，弱密码等于裸奔；
- **密钥**：一对文件——私钥（只在你电脑上，打死不给别人）+ 公钥（放在
  服务器的 `~/.ssh/authorized_keys`）。登录时服务器出一道只有私钥能解的
  题目，全程不传任何密码。**没有私钥的人连门都摸不到。**

📍 对照你的系统：
- 私钥 `~/.ssh/agentlink_vps`（ed25519 算法，比 rsa 短且更安全）；
- 登录命令 `ssh -i ~/.ssh/agentlink_vps root@<VPS_IP>`；
- 加固：`/etc/ssh/sshd_config.d/99-agentlink.conf` 写了
  `PasswordAuthentication no`——密码通道彻底关闭，只认密钥。

**为什么当时网页终端能用**：腾讯云控制台的"登录"走它自己的内部通道
（用你的腾讯云账号身份），不经过 22 端口——这是救命的兜底，SSH 配坏了
也能进去修。

### 3.5 排查五件套

排障的核心思路：**分层，从近到远逐跳测试**。五件套按出场顺序：

1. `netstat -ano`（Windows）/ `ss -tlnp`（Linux）：进程还在听端口吗？
2. 看进程自己的日志（`frpc.log`、`journalctl`）——它自己说发生了什么？
3. `curl` 打一枪看状态码：401 = 对方活着但要 token（好信号！）；
   000 = 连不上（链路断）。
4. `dig`：DNS 这一跳通吗？问权威服务器绕开缓存。
5. `whois`：域名本身的状态健康吗？

## 四、内网穿透 —— 这套系统的核心魔法

### 4.1 frp 架构

回顾 1.2：外面进不了 NAT 后面的家。frp（fast reverse proxy）的解法是
**让家里主动连出去，把这条连接变成双向管道**：

```
                      ┌─────────── VPS（公网，谁都可达）───────────┐
手机 ──HTTPS:443──▶ Caddy ──▶ 127.0.0.1:8799 frps ◀═══ 隧道 ═══╗  │
                      └────────────────────────────────────────┼──┘
                                                            控制连接+数据连接
                                                                ║
                                              家里 PC frpc 主动发起（NAT 放行）
                                                                ║
                                                    frpc ──▶ 127.0.0.1:8799 daemon
```

两个角色：

- **frps**（server，VPS 上）：守在 7000 端口等 frpc 来连；对外把 8799 映射出去。
- **frpc**（client，你 PC 上）：主动连出去注册自己，之后 frps 收到手机请求
  就通过这条隧道递给 frpc，frpc 转给本机的 daemon，响应原路返回。

NAT 完全无感：从它的视角，只是"内网一台机器往外打了个连接，一直没断"。

📍 对照你的系统：
- 服务端 `/etc/frp/frps.toml`（VPS）：`bindPort=7000`、`auth.token`（接头暗号）、
  `transport.tls.force`（隧道本身也加密）、`proxyBindAddr=127.0.0.1`（8799 只给本机 Caddy 用）；
- 客户端 `~/.agentlink/frpc.toml`（PC）：`localPort=8799`（家里的真服务）、
  `remotePort=8799`（VPS 上对外映射的口）、`loginFailExit=false`（断了就无限重试）。

### 4.2 为什么流量要"绕道"

手机 → VPS → 家，明明可以"直线"（其实不行，见 1.2），隧道多绕了一跳。
代价是延迟变成两段之和（手机→香港 + 香港→家）；收益是：

1. **可达性**：唯一能让外网摸到 NAT 后面设备的通用办法之一；
2. **位置优势**：VPS 在公网骨干上，手机无论在哪（4G/5G/别人家 WiFi）都
   能稳定连到它——家宽线路对外的质量是不可控的。

### 4.3 同类方案对比

| 方案 | 原理 | 适合 | 你的情况 |
|---|---|---|---|
| **frp + VPS** | 主动连接变隧道 | 有 VPS、要完全掌控 | ✅ 现役 |
| Tailscale/ZeroTier | 点对点 VPN 组网 | 怕麻烦、不想维护服务器 | 手机要装 App，当时否了 |
| Cloudflare Tunnel | cloudflared 连 CF 边缘 | 有域名、不想买 VPS | 国内直连 CF 不稳 |
| DDNS + 端口转发 | 家宽公网 IP + 路由器映射 | 运营商给公网 IP | 家宽多为大内网，不可行 |

## 五、Windows 侧 —— 你家电脑这头

### 5.1 计划任务与后台进程

Windows 的"开机自启"正式名称是**任务计划程序**（Task Scheduler）。我们建了
两个任务：`AgentLink-daemon` 和 `AgentLink-frpc`，触发器是"用户登录"。

这里踩过一个真实的坑：任务默认以**可见的控制台窗口**运行那两个 `.cmd`
脚本——窗口被误关，整棵进程树（cmd → bun/frpc）跟着死掉，外网链路就断了。

修复方案：`wscript`（Windows 自带的 VBScript 宿主）以**零窗口**方式启动
脚本——桌面上什么都看不见，自然也没有能被关的东西。

📍 对照你的系统：
- 启动脚本 `~/.agentlink/start-daemon.cmd`、`start-frpc.cmd`
- 无窗口启动器 `~/.agentlink/run-hidden.vbs`
- 日志 `~/.agentlink/daemon.out.log`、`~/.agentlink/frpc.log`

### 5.2 路由表与代理：Clash 那次事故

**路由表**是操作系统里的一张表："去某 IP 段的包，从哪个网卡、经由哪个
网关发出去"。`route print` 可看。默认有条"默认路由"（0.0.0.0/0 = 去哪儿
都这么走）。

Clash 开 **TUN 模式**时会创建一个虚拟网卡，把默认路由抢过来——于是你
所有流量都进了代理。这本身正常，但代理节点把 SSH/frpc 这类"非网页流量"
掐断了（就是那次 `Connection closed by remote host`）。

**静态路由**是破解法：加一条比默认路由**更精确**的规则——

```
route add <VPS_IP> mask 255.255.255.255 192.168.1.1 metric 1 -p
```

含义："去这一个 IP，永远走物理网关、直连"。/32（单个 IP）比 /0（所有地址）
精确，必定优先匹配；`-p` 让它重启后仍在。Clash 再怎么抢默认路由都影响不到它。

另一个相关概念：Clash 的 **fake-ip** 模式会接管 DNS，本机 `nslookup` 任何
域名都返回 `198.18.x.x` 假地址（先骗你连上 TUN 再说）。所以在本机查 DNS
结果是不可信的，要查真实状态去 VPS 上用 1.1.1.1 的 DoH 接口（见 1.4）。

### 5.3 命名管道：daemon 怎么"听见"桌面版 Codex

**命名管道**（Named Pipe）是同一台机器上两个进程之间的通信通道，
Windows 上形如 `\\.\pipe\名字`。Codex 桌面版启动时创建 `\\.\pipe\codex-ipc`，
AgentLink 的 daemon 连上去，以"follower"身份订阅会话快照、委托发消息/
审批——全程不出本机，这也是"接管同一会话而不打架"的基础。

（顺带：daemon 因此必须和桌面版跑在**同一个用户会话**里，所以计划任务的
触发器是"登录时"而不是"开机时"——开机未登录的会话 0 里连不上桌面版的管道。）

## 六、把一切串起来 —— AgentLink 完整链路漫游

```
手机浏览器/PWA
  │ ① HTTPS + WSS（443）：TLS 加密，token 不裸奔          → §2.1/2.2
  ▼
VPS 上的 Caddy
  │ ② 自动证书（Let's Encrypt 续期）、gzip 压缩、反代     → §2.2/2.3
  ▼
VPS 上的 frps（127.0.0.1:8799）
  │ ③ 隧道服务端：token 认证 + 强制 TLS                    → §4.1
  ▼ ═══════════ frp 隧道（PC 主动发起，NAT 放行）═══════════ → §1.2
家里 PC 的 frpc
  │ ④ 转给本机 8799
  ▼
AgentLink daemon（bun，计划任务无窗口运行）
  │ ⑤ Bearer token 认证、会话状态机、事件总线              → §5.1
  ├─▶ 命名管道 → Codex 桌面版（观察/接管真实会话）          → §5.3
  ├─▶ rollout 文件尾读（额度数据）                          → §3.2
  └─▶ codex app-server 子进程（自建会话）
```

手机上每一次"下拉刷新"，走的都是这条链；任何一环断了，第七章的排障法
都能定位到是哪一环。

## 七、排障手册（SOP）—— "连不上了"怎么办

**总原则：从近到远，逐跳验证。别上来就重启一切。**

```
第 1 跳：daemon 还活着吗？（家里 PC）
  netstat -ano | findstr 8799        → 有 LISTENING = 活着
  没了 → 看 ~/.agentlink/daemon.out.log 结尾；重启见第 4 步

第 2 跳：frpc 隧道通吗？（家里 PC → VPS）
  tail ~/.agentlink/frpc.log         → "login to server success" 且无新报错 = 通
  报错 timeout → ① 云控制台 7000 防火墙规则还在吗 ② Clash TUN 又开新花样了？
  （静态路由在，一般不是它；重启大法见第 4 步）

第 3 跳：VPS 侧全通吗？（SSH 上去测）
  ssh -i ~/.ssh/agentlink_vps root@<VPS_IP>
  systemctl is-active frps caddy     → 都应 active
  curl -o /dev/null -w '%{http_code}\n' https://<你的域名>/api/v1/status
                                      → 401 = 全链路健康（要 token 是正常的）
                                      → 000 = Caddy/证书/DNS 问题，看 journalctl -u caddy

第 4 步：重启的正确姿势（Windows）
  powershell "Start-ScheduledTask AgentLink-daemon; Start-ScheduledTask AgentLink-frpc"
  （它们已是无窗口运行，不要去找"黑窗口"——没有窗口可看，看日志文件）

第 5 步：还不行 → DNS / 域名层
  VPS 上：curl DoH 查 A 记录（1.4 的命令）；whois 看状态码有没有 serverHold
```

**症状速查表**

| 症状 | 最可能 | 看哪 |
|---|---|---|
| 手机打不开页面（转圈/证书错误） | DNS 或 Caddy | 第 3/5 跳 |
| 页面能开但"连接中…"不恢复 | frpc 隧道断 | 第 2 跳 |
| 会话列表空/加载失败 | daemon 死了 | 第 1 跳 |
| 内容停住不更新（重连后恢复） | WS 假死（有心跳，等 45s 自愈） | §1.3 |
| 发指令报"指令发送失败" | 额度用尽 / 桌面端拒绝 | 会话页红条的具体文案 |

## 八、进阶附录（选读）

### 8.1 GFW 与线路质量

跨境流量要过国际出口，晚高峰拥塞丢包是常态。云厂商/机房的"优化线路"
本质是买更好走的路：电信 CN2 GIA、联通 9929、移动 CMI。DMIT 这类商家
溢价卖的就是这个。判断线路好坏的土办法：晚高峰 `ping` 看延迟抖动和丢包。

### 8.2 监控与看门狗

现在每个组件都有"崩溃自启"（systemd / 计划任务失败重启），但没有
"活着但卡死"的检测。下一步可选：一个 5 分钟一次的定时任务，curl 不通
就重启对应服务并写日志——需要时再加，别过度工程。

### 8.3 日志轮转

日志文件只增不减（`frpc.log`、`daemon.out.log`）。个人量级一年也涨不了
多少，暂时不管；真要处理时，Linux 用 logrotate，Windows 侧可以在启动
脚本里加个"超过 N MB 就截断"的逻辑。

### 8.4 加一个新服务的通用套路

以后想加 ntfy 推送之类的东西，套路是固定的：

1. VPS/PC 上装好，手动跑通；
2. 写成 systemd 服务（VPS）或计划任务 + 无窗口启动器（PC）；
3. 防火墙放行需要的端口（控制台）；
4. 把配置和日志位置记进部署备忘；
5. 重启一次机器，验证全自动恢复。
