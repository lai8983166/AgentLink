## 可重复的预览检查

安装工作区依赖和 NSH 工具链后运行：

```bash
node native/scripts/build.mjs test
node native/scripts/visual-review.mjs /path/to/browser
```

第二条可省略浏览器参数，让 NSH 使用可用浏览器。无图形加速的 Linux 环境可传入自行配置软件渲染的 Chromium 启动脚本。截图写入被忽略的 `native/.tools/visual-review/workspace/native/artifacts/`，不改生产清单，不连接真实后台。当前自动截取 16 个页面/状态；截图生成成功仍需人工查看，不能代替视觉判断。追加 `--classic` 在隔离副本检查保留主题，输出到相邻 classic 目录。

## 明确保留的差异和未验证项

- NSH 使用固定矢量图标代替受系统 emoji 字体影响的工具/目录等图标，保持语义和占位；新增任务保留显式关闭按钮。
- 设置显示 NSH 自己的版本，更新通过 APK；网页缓存更新与浏览器键盘诊断不移植。NSH 保留可用能力内的审批策略入口及发送结果核对。
- 未获得服务端批准能力时不会显示可点击批准入口；禁用控制不因样式对齐而放开。
- 中文字形/字重、系统字号、键盘、安全区、弹层手势、系统权限对话框和长列表性能尚未取得本轮真机证据。浏览器截图不是安卓设备截图，也不据此宣称逐像素一致。
- 首页刷新回归仍包含连续列表事件不增加 HTTP、后台核对不显示刷新反馈。下拉指示器只绑定实际下拉动作，不复用初次加载/手动刷新状态。

以后修改原版页面时，应同时核对本表对应 NSH 页面和其空态、错误态、操作后状态；先更新共享样式，再检查截图，不能仅凭样式参数相同判定完成。
